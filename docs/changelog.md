# 版本与里程碑记录

按时间倒序记录功能上线与里程碑事件。设计细节见 `specs/`，运行与排查见 `runbooks/`。

## V0.5.1 修复：反向代理下写请求被判跨站（2026-09-21）

**交付**：测试环境实测登录时发现的故障——浏览器发起登录返回 403「请求来源不被信任」，账号与口令本身没有问题。

- **原因**：写入操作的 CSRF 同源校验拿 `Origin` 的 `netloc` 与请求自身的 `Host` 逐字符比对。浏览器的 `Origin` 永远带端口（`http://118.145.238.50:12439`），而 nginx 的 `proxy_set_header Host $host` 转发时把端口吃掉了，两边必然对不上，于是一次正常登录被判成跨站。V0.5 起该逻辑就在，只是此前没有在生产路径上真正登录过。
- **修复分两处**：nginx 改为转发 `$http_host`（保留端口）并补上 `X-Forwarded-*`；后端同时认 `X-Forwarded-Host`，并且当转发来的 Host 不带端口时按同源放行（端口那一层仍要求：显式写了就必须一致）。两层都做，是因为换回 `$host` 或外层再加一层网关时同样会踩到。
- **与安全无关的放宽**：判定仍要求主机名一致，`https://evil.example.com` 一类依旧 403；`X-Forwarded-Host` 有多个取值时只取最靠近客户端的一跳。
- **账号、口令、数据库、前端一个字未改**：前端 51 项测试与后端 469 项测试全部通过。该 403 与「空库返回 503」是两回事，排查时不必怀疑密码。

## V0.5.1 账号与会话入库（2026-09-21）

**交付**：把 V0.5 的环境变量账号改成数据库账号，登录态从无状态签名票据改成 `sessions` 表，新增冷启动初始化脚本。本版实质上是把 V0.5 明确记在账上的短板补掉：那时「无法单独踢掉一个用户，只能换签名密钥让全员重登」，现在可以按会话、按账号精确撤销。方案与边界记账见 `specs/v0.5.1-design.md`。

- **账号入 `users` 表，`AUTH_USERS` 与 `AUTH_SESSION_SECRET` 一并退休**：数据库成为账号的唯一来源，`.env` 里不再有一份需要与人手同步的账号清单。两个环境变量从代码、配置样例与文档中移除，不配置它们不再产生任何告警。口令哈希与校验逻辑不变（仍是标准库 PBKDF2-HMAC-SHA256，24 万次迭代），只是存储位置从环境变量换成 `users.password_hash`。
- **登录态入 `sessions` 表，令牌不再是签名票据**：令牌是 256 位随机串，**库里只存 SHA-256 摘要**，Cookie 里放明文令牌——拿到数据库文件也换不出一个可用会话。摘要不加盐、不用慢哈希：令牌是高熵随机串，没有字典可猜，慢哈希只会让每个请求白花几十毫秒。留在原地的签名票据已经无用：它只能证明「这张票是我签发的」，证明不了「这张票现在还有效」。
- **撤销能力是本版的核心收益**：退出登录会真的删掉服务端那一行，旧令牌即便被抄走也再无用处（V0.5 的「登出」只对当前这台设备成立）；同一账号的两张会话互不影响，退出其中一台不踢另一台；改口令或删账号会清掉该账号的全部旧会话。删账号另有外键级联兜底，不留指向空账号的活会话。
- **有效期分两段**：滑动窗口 12 小时（`AUTH_SESSION_TTL_SECONDS`）加绝对上限 7 天（`AUTH_SESSION_ABSOLUTE_TTL_SECONDS`）。只有滑动没有上限等于一次登录永久有效，只有上限没有滑动则连续工作一整天会被中途要求重新登录。续期写入做了节流——剩余时间不足半个窗口才写库，否则一次页面加载会变成几十次 UPDATE。
- **新增 `python -m app.auth.init_admin`**：交互式建管理员（口令不回显、两次不一致即中止、账号重复时不静默覆盖而是单独问一次），`--list` 查看已有账号，`--username/--password/--display-name` 走非交互供自动化使用。脚本自己建表，空库也能直接跑。
- **「没配账号」的语义从配置错误变成部署未完成**：空库是冷启动的正常状态，登录接口因此返回 503 并写明要跑 `init_admin`，不再是 V0.5 那条 500「服务端用户配置无效」。不写清楚的话，空库的表现是「什么口令都不对」，只会让人反复怀疑记错了密码。
- **前端与接口契约一个字未改**：Cookie 仍是 `HttpOnly` + `SameSite=Lax` + `AUTH_COOKIE_SECURE`，三个鉴权端点的路径与响应体不变，`session.ts` 无需改动，前端 51 项测试原样通过。每次请求多发一次主键查询（查会话），这是把会话收进数据库的直接代价。
- **过期会话清理不需要定时任务**：撞上即删，服务启动时再扫一遍「登录过一次就再没回来」的那些。

**未完成**：不做改口令的界面入口（仍走命令行）、不做账号增删改接口、不做角色与权限（`users.role` 列已落库但无任何判定依赖它）、**仍不做用户隔离**（任务数据不按账号切分）；不做在线设备查看与批量踢人、不做登录失败审计、不做单账号会话数上限、节流仍在进程内存里（多实例部署需换成共享存储）。测试环境的容器内建号与真实登录本机未覆盖，见 `specs/v0.5.1-design.md` §6。

## V0.5 用户登录（2026-09-20）

**交付**：加入最小范围的用户机制——外部访问者先登录才能进入工作台，所有数据接口整组收口。本版不含注册、角色与用户隔离；账号由后端手工配置，所有登录用户共享同一套任务数据。方案与边界记账见 `specs/v0.5-design.md`。

- **登录态用 HttpOnly 签名 Cookie，不建会话表**：票据是「账号 + 签发时间 + HMAC 签名」，服务端不保存任何东西，进程重启不掉线（本地开发开着 reload，这一点尤其重要）。选 Cookie 而不是 Bearer 令牌的直接原因是**下载口**：`transcript.txt` 与 `review.md` 由浏览器直接发起请求，不带 `Authorization` 头，只有 Cookie 能覆盖到它们。
- **无注册，初始化用户写在 `AUTH_USERS`**：格式为逗号分隔的 `账号:口令哈希[:显示名]`，哈希用新增的 `python -m app.auth.passwd` 生成（支持交互式、`--generate` 随机口令、`--secret` 生成签名密钥、`--check` 校验格式）。明文口令不写进任何文件、不进仓库。
- **口令用标准库 PBKDF2-HMAC-SHA256**：迭代 24 万次，存储格式自描述（`pbkdf2_sha256$迭代$盐$哈希`），日后换算法不必迁移数据。不引入第三方口令库——本版用户来自环境变量，用不到强度校验与多格式兼容那套能力。
- **失败节流**：同一账号 1 分钟内连续失败 5 次即拒绝，直到窗口滑过；成功一次立即清零。登录失败对外只有一句话「账号或密码不正确」——区分「账号不存在」与「口令不对」等于把「哪些账号存在」白送给对方，具体原因只写服务端日志。
- **CSRF 底线**：`SameSite=Lax` + 写操作校验 `Origin` 与本请求 `Host` 同源。没有 `Origin` 的请求放行——那是 curl 与脚本发出的，本就拿不到 Cookie，拦下来只会挡住合法的运维操作。
- **接口收口在装配处，不在逐个端点**：`main.py` 给四个业务路由整组挂上鉴权依赖，漏掉一个端点就等于漏掉一条数据出口，集中在装配处只有一个地方需要检查。`/health` 与登录接口保持公开（探针不登录，登录接口必须先可达）。
- **健康检查收敛回显内容**：原先挂在公开 `/health` 上的模型型号、存储桶名与缺失凭据项名，移到登录后的 `GET /api/auth/status`。探针只需要「服务是否可用」，「用了哪个模型、缺哪个密钥」不该对未登录者公开。
- **前端未登录时只渲染登录页**：`LoginDialog` 弹层改为整屏 `LoginPage.tsx`，凭据真的送后端比对，失败原因原样呈现；角色下拉去掉（本版没有角色机制，留着等于暗示存在权限差异）。登录态在 HttpOnly Cookie 里前端读不到，因此启动先查一次会话，把「正在载入」「未登录」「已登录」分成三态——混在一起会让刷新页面时先闪一下登录页。任一接口返回 401 都会退回登录页，并区分「会话失效」与「主动退出」两种文案。
- **签名密钥未配置时可用但不安全**：`AUTH_SESSION_SECRET` 留空会每次启动随机生成，服务照常可用，但重启即让所有人掉线；启动日志与登录后的状态接口都会把这条隐患写出来。换掉这把密钥等价于立即作废所有已签发的票据——这是本版唯一的「踢人」手段。

**未完成**：不做注册与改口令、不做登录审计日志、不做会话踢出与在线查看、不做角色与权限、**不做用户隔离**（任务数据不按账号切分，数据库里也没有记录「谁上传的」，将来要做隔离必须补列并在写入时带上，不是加个查询条件就行）；不改 `records` 与任务表结构。

## V0.4.1 任务详情拆分为三个子页（2026-09-18）

**交付**：把原先一屏到底的任务详情拆成「视频信息 / 内容理解 / 复盘分析」三个子页，让不同功能区解耦。只动前端信息架构，后端、API 与业务链路一概未改；切分、识别、复盘的判定与轮询逻辑也未变，只换了承载它们的容器。

- **三个子页各回答一个问题**：视频信息＝这条录屏处理得怎么样、切出了什么（上传完成后自动进入）；内容理解＝讲的是什么（处理完成后开放，点按钮触发识别）；复盘分析＝讲得怎么样、下一场改什么（识别完成后开放）。原先处理流程、媒体信息、切片表、识别汇总、识别全文、复盘结论堆在同一条竖轴上，页面被拉到几屏长，确认一件事要先滚很久。
- **开放条件看产物，不看操作记录**：处理结束（成功或失败）即开放内容理解，识别出过条目即开放复盘分析。处理失败的任务因此仍能进内容理解页——失败原因与单片重试入口在那里才看得见。已开过复盘的任务不受识别条件约束，历史结论照常可看。
- **子导航三项常显**：未达条件的子页置灰并写明原因（如「视频处理完成后开放」），用户看得到完整链路与下一步要做什么，而不是面对一个消失的入口。点到一个还没开放的子页时自动退回可进的那一页并说明。
- **子页写进地址**：新增 `#/tasks/:id/media|understanding|review`，刷新与前进/后退在子页之间同样成立。打开一条任务时按进度落在最靠后的可进子页——已复盘的直接停在结论，少两次点击。
- **切片与识别明细改分组呈现**：一条长直播动辄几十片，整表铺开会把页面拉长到无法核对。两处都改为每组十条，配「第 X–Y 条 / 共 N 条」与首末组、相邻组。序号、时间轴位置条与覆盖校验仍按整场坐标计算，不因分页错位。
- **识别全文默认展示条目**：加工过的条目才是可读内容，进页即拉取展示，并在条目上补出语气标注。此前并排的等宽纯文本全文不再占版——它与下面的条目是同一批内容的两种排版，摆两份只会让人不知道该核对哪一份；纯文本降级为「下载 txt」。
- **未做**：不做子页间的自动推进（处理完成后不替用户跳到识别页），也不做子页级权限与分享链接。

## V0.4 前端界面重构（2026-09-18）

**交付**：只改前端的信息架构与视觉表达，不动后端、不动 API、不动业务功能。技术栈仍是 React + Vite + 手写 CSS，未引入 UI 库、路由库与图标库。方案与效果图见 `ui_design/`。

- **建立 Design Token**：`styles.css` 的 `:root` 收口了全站色板（页面 `#F7F8FA`、内容面 `#FFFFFF`、文字三档灰、边框 `#E5E7EB`）、品牌蓝 `#2563EB` 与四态色。字号只留 24/16/14/13/12 五级，间距只留 4~48 八档，圆角三档。此前散落在组件里的 13px / 17px / 21px 这类随手值全部归并。
- **版式母题改为企业级数据工作台**：去掉深藏青页眉、深色强调块与卡片套卡片；页眉改 56px 白底，侧栏改 232px 白底并只用一条极浅分隔线。面板只在需要视觉隔离时使用（白底 + 1px 边框 + 10px 圆角，无阴影）。
- **信息架构重排**：新增轻量 hash 路由（`#/new`、`#/tasks/:id`、`#/analytics`、`#/settings`），刷新后停在原处且浏览器前进/后退可用。侧栏改为主导航（任务列表 / 数据分析 / 设置）+ 最近任务，后两项是导航结构上的预留入口，标注「未接入」并给出说明页，不做空白页伪装成功能。
- **新建任务页重做**：上传区改为页面视觉中心（虚线边框、拖拽即传、hover 变蓝），右侧固定一栏「处理说明」讲清后台四个步骤。上传状态机（断点续查、补分片、合并入库、轮询）从 `Workbench` 抽出到 `IntakePage` 时**一行逻辑未改**。
- **任务详情页重做**：顶部为任务身份（缩略占位 + 文件名 + 状态 + 时间/体积/分辨率/编码）与操作入口；「处理流程」改横向节点连线，已完成绿、当前步骤品牌蓝；「媒体信息」改两列数据布局去掉横向分割线；「切分结果」改专业 Data Table（浅灰表头、极浅行线、hover 反馈、状态小图标）。分阶段的判定逻辑（`STAGES` 与 `stageState`）保持原样，只换渲染。
- **状态表达降级为辅助信息**：任务与片段状态统一为「小圆点/小图标 + 文字」，不再用大面积彩色 Badge。
- **无视频缩略图接口**：顶部缩略区用与实际分辨率同比例的占位块表达「这是一条竖屏录屏」，不为本次重构新增视频处理逻辑。
- **「查看报告」按钮**：绑定既有的 `GET /api/tasks/{id}/review.md`，无复盘结果时禁用，未新增接口。
- **未做**：数据分析与设置只有说明页，聚合接口与配置读写都还需后端起独立任务；侧栏搜索的筛选范围是「最近任务」列表（后端暂无检索接口），文案已如实写为「筛选最近任务」。

## V0.3 直播内容复盘（2026-09-18）

**交付**：在整场语音转写之上接入复盘节点，形成「上传 → 切分 → 识别 → 复盘」的完整闭环。本版按任务方要求把原预置的 V0.3（内容时间线与关键事件）与 V0.4（复盘报告与 MVP 闭环）合并为一版；原 V0.3 中依赖视频回看的两条验收要点随切片播放功能的撤销一并取消。

- **复盘输入是整场语音转写**：识别完成后把所有分片的语音结果按原视频时间轴拼接，作为复盘节点的输入，并带上每句的语气标注。失败与未识别的片段在输入里显式声明缺失，避免模型把缺口当成「这段时间没人说话」。
- **准则按可用输入裁剪**：任务方提供的《直播复盘分析准则》被裁剪为「仅有语音」的版本——保留业务背景与评判口径、内容主题分类、讲车表达方式、六维分析与证据分级；删除巨懂车数据、漏斗瓶颈定位、画面/OCR/行为识别、主播档案与跨场对比、100 分制评分。三处主动偏离（漏斗仅作背景、不做评分改定级、禁止历史比较）在 `specs/v0.3-design.md` 中记账。
- **分析等级由程序兜底**：模型只能看到转写文本，看不到缺口，因此等级按真实覆盖面校正——成功率低于 50% 强制「受限」，有失败片段时不得为「完整」。
- **识别题面增加语气捕捉**：识别 Prompt 要求判断每句的语气与情绪并写入 `tone` 字段，供复盘的表达方式与语气维度使用。语气是主观估计，听不出时写「语气不明」，不允许臆测。
- **长直播分批分析**：转写超出单批上限时按记录边界切批，逐批调用后**结构性合并**（去重、按时间排序、按准则截断 TOP3），不额外发起摘要调用。
- **失败片段不阻断复盘**：缺口数量进输入、也写进结论的等级与缺口清单；一片失败就让整场出不了结论，反而不如带着明确警示给结论。
- **复盘可续跑**：进程重启把停在 `running` 的复盘退回待跑并重新入队——复盘输入已落库，续跑最多重跑一次文本调用，不触碰识别。
- **界面新增「复盘结论」块**：先讲边界（分析等级与依据）再讲结论，每条发现标注证据等级与时间码，TOP 问题与下一场动作分列，「本场不足以判断」单独成块；另提供 Markdown 报告下载，与页面同源。

**未完成**：「复盘结论是否有助于改进直播」需在测试环境用真实整场直播人工评估后给出，本版只把判断所需的数据（结构化结论、各批原始返回、用量、归一告警）留档。

## V0.2.1 上传与识别的中断恢复（2026-09-18）

**交付**：把「关闭页面不影响后台处理」从切分链扩展到上传与识别——两处原先都依赖页面在场。

- **上传入库归后端所有**：分片传输仍必须由浏览器驱动（原文件在用户磁盘上），但「合并 → 上传对象存储 → 建任务 → 入队」抽到 `backend/app/uploads.py`，由接口与启动恢复共用。关页面时若分片已收齐，容器下次启动会自己把这次上传做完；缺片的会话保持原状等待续传，不会被判失败。
- **浏览器只留凭据**：前端把当前上传会话记在 `localStorage`（24 小时有效），重开页面时提示「这次上传还没传完」，选一次同一个文件即补传缺片；分片已收齐时直接补上完成请求，不必再选文件。
- **识别自动续跑**：进程重启把停在 `running` 的识别退回 `pending` 并重新入队，续跑只补未完成的片段。已成功的片段与从未启动过识别的任务都不受影响，因此重启不产生模型费用。
- **恢复是幂等的**：入库链路在对象已在或本地副本已在时不再重传；识别续跑不重复触发已成功片段的模型请求。

## V0.2 基于切片的多模态识别（2026-09-17）

**交付**：接入音画理解模型，对 V0.1 切分出的片段执行语音识别，并把结果按原视频时间轴汇集为可核查的整场全文。

- 模型接入走 OpenAI 兼容的 `responses` 接口（`backend/app/llm/`），供应商与型号由 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL_NAME` 决定，不锁定厂商；单次请求超时独立配置（默认 900 秒），SDK 内建重试关闭，重试策略集中在接入模块内。
- 识别输入是片段对象键**现签**的预签名 URL，不引入 TOS 内网 client，也不把凭据与 URL 写进日志。
- 输出解析对模型的不稳定格式做了容错，并**如实记账**：被丢弃的条目在片段上留告警，`[]` 与解析失败严格区分，越界时段只标记不裁切。
- 识别是独立阶段：手工触发、可单片重试、已成功的片段不重复计费、配置缺失时整场明确拒绝而不是逐片失败。
- 界面新增「识别结果」块（整场汇总 + 逐片明细 + 可复制/下载的全文），失败片段可单独重新识别。

**未完成**：识别质量的验收结论（统一识别方案能否继续采用、是否需要补充 ASR）需在测试环境用真实直播素材人工核查后给出，本版只把判断所需的数据留档。
