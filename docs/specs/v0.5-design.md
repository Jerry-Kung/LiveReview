# V0.5 设计文档：用户登录

> 本文是 V0.5 的设计文档，属 `specs/` 下的开发任务期间产出。
> 依据：任务方本次的规划要求。
> 定位：记录本版的方案取舍与边界记账，不规定函数签名与字段清单（那些看代码即可）。

## 1. 本次范围

任务方给出的三条要求：

1. 提供登录页面，外部访问者先登录才能进入主页面操作。
2. 暂不提供注册，后端手工配置初始化用户与口令。
3. 暂不提供用户隔离，所有用户共享同一套项目数据。

本版按 **V0.5.1 后端鉴权地基 → V0.5.2 全量接口收口 → V0.5.3 前端登录与全局 401** 三步顺序实现。
三步之间没有可并行的分支：收口依赖地基提供的依赖，前端依赖后端已经能给出真实的 401。

## 2. 方案取舍

### 2.1 登录态用签名 Cookie，不建会话表

会话票据走 HttpOnly Cookie，内容为 `base64url(账号).签发时间.HMAC-SHA256 签名`，服务端不保存任何东西。

选它的直接原因是**下载口**：`GET /api/tasks/{id}/transcript.txt` 与 `review.md` 由浏览器直接发起，
不带 `Authorization` 头，只能靠 Cookie 携带凭证。用一个 `Authorization: Bearer` 的令牌方案会漏掉这两个口，
而它们给出的正是整场转写与复盘结论。

在此之上，无状态还避开了三件事：进程重启掉线（本地开发开着 reload，会更频繁）、会话表的过期清理、
以及多写一处并发。代价有两处，本版明确接受：

- **无法单独踢掉一个用户**。要立刻作废已签发的票据，只能更换 `AUTH_SESSION_SECRET`，代价是全员重登。
  本版用户数是个位数，这个代价值得。
- **无法主动续期或记住「上次登录时间」**。票据只在有效期内可用，没有滑动续期。

### 2.2 口令用标准库的 PBKDF2，不引入第三方口令库

`hashlib.pbkdf2_hmac` 足够覆盖「校验一个口令」这一件事，选它省掉一个需要跟进的依赖。
存储格式自描述（`pbkdf2_sha256$迭代次数$盐$哈希`），日后换算法不必迁移数据；
迭代次数取 24 万（当前建议量级），登录时约几十毫秒，对交互无感。

不引 `passlib` / `bcrypt` 的另一个原因：本阶段用户由环境变量配置，没有「校验强度、生成临时口令、
兼容多套哈希格式」这些需求，引进来的是用不到的能力与随之而来的版本约束。

### 2.3 CSRF 底线：SameSite=Lax + 写操作校验 Origin

Cookie 是浏览器自动携带的凭证，跨站请求会自己带上，因此 CSRF 必须自己处理。两道措施：

- `SameSite=Lax`：跨站发起的写请求不带这张 Cookie，挡住绝大多数场景。
- 写操作（非 GET/HEAD/OPTIONS）校验 `Origin` 与本请求的 `Host` 同源。`SameSite=Lax` 挡不住同站子域，
  也挡不住日后有人为了跨域把它放宽，这一条是兜底。

**没有 `Origin` 的请求放行**：那是非浏览器客户端（curl、脚本、探针）发出的，它们本就拿不到 Cookie，
拦下来只会挡住合法的运维操作，而不会提高安全性。

### 2.4 健康检查保持公开，但收敛回显内容

`/health` 被容器 healthcheck 调用，探针不会登录，因此它必须公开。但它原先会回显模型型号、
对象存储桶名与缺失的凭据项名——这些对未登录者没有用处，却是一份现成的情报。
V0.5 起 `/health` 只回 `status` / `service` / `version` / `environment` / `database` / `storage`
（storage 只给可用性），明细移到登录后的 `GET /api/auth/status`。

### 2.5 失败节流放在进程内存

同一账号 1 分钟内连续失败 5 次即拒绝，直到窗口滑过。目标是挡住「对着一个已知账号不停试口令」，
不做长期风控。单实例部署下内存计数够用；多实例部署时要换成共享存储，届时 `LoginThrottle`
的接口形态不必改。

登录失败对外只有一句话「账号或密码不正确」：区分「账号不存在」与「口令不对」等于把
「哪些账号存在」白送给对方。具体原因只写服务端日志。

## 3. 界面

未登录时**整屏只给登录页**，不渲染工作台。这不只是界面遮掩：工作台里的每个请求都要带会话 Cookie，
后端会把未登录的请求一并拒掉，因此省掉的是一串注定失败的请求，真正的边界在后端。

三处与旧版的差别：

- 旧版 `LoginDialog` 是一个弹层，把「账号 + 角色」提交给前端内存，不校验口令，界面上也如实写着「预留功能区」。
  本版改成真实登录，凭据送后端比对，失败原因原样呈现。
- **角色下拉去掉**：本版没有角色机制，让它留在界面上等于暗示存在权限差异。
- **页眉账号区接真实会话**，显示名可能与账号不同（如「测试用户」与 `tester`），两行都给出来便于核对身份。

会话在 HttpOnly Cookie 里，前端读不到，因此壳层启动时先问一次 `GET /api/auth/session`，
据此在三态之间选择：还没问完（给一行「正在载入」）、未登录（登录页）、已登录（工作台）。
把「还没问完」与「未登录」分开是必要的——混在一起会让刷新页面时先闪一下登录页再跳进工作台。

任一接口返回 401 都会通知壳层退回登录页，并区分为「会话失效」与「主动退出」两种文案：
前者要说清是会话过期而非用户操作有误，后者要给一句确认。**未登录时的 401 不报「会话失效」**，
那是正常的，不该被解释成出了问题。

## 4. 未做（边界记账）

- **用户增删改与改口令**：需要入库，本版账号在环境变量里。运维方式见
  `docs/runbooks/deployment.md` 的「账号运维」。
- **登录失败审计日志**：目前只有进程日志里的一行，没有可查询的记录。
- **会话主动踢出与查看在线**：无状态票据不支持，只能换密钥全员重登。
- **角色与权限**：本版所有登录用户等价，没有只读账号、管理员之分。
- **用户隔离**：任务数据不按账号切分（任务方明确本版不做）。数据库里也没有记录「谁上传的」，
  因此将来要做隔离必须补一列并在写入时带上，不是加个查询条件就行。
- **静态页面的服务端拦截**：SPA 页面本身不含数据，未登录者拿到的是一个空壳，
  拦它挡不住任何信息。数据接口才是边界，本版把它全数收口。
- **登录接口的验证码 / 二次验证**：仅靠节流，没有验证码。

## 5. 验收标准

1. 未登录访问任意 `/api` 数据接口返回 401，`/health` 与 `/api/auth/login` 保持可达。
2. 用配置的初始化账号可登录，错误账号或口令返回统一文案且不透露账号是否存在。
3. 登录后刷新页面仍保持登录，退出登录后立即回到登录页且旧票据不再可用。
4. 伪造、过期、用其他密钥签发的票据一律被拒；账号从配置中移除后其旧票据立即失效。
5. 跨站发起的写请求（带 Cookie）被拒，同源写请求正常。
6. 前端未登录时只渲染登录页，不发起任务列表请求。

自动化覆盖见 `backend/tests/auth/`（地基、HTTP 契约、路由收口三组）与
`frontend/src/App.test.tsx`（登录门槛一组）。
