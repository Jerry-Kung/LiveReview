# V0.1.1 设计文档：项目骨架与运行环境

> 本文是 V0.1.1（项目骨架与运行环境）的设计文档，属 `specs/` 下的开发任务期间产出。
> 依据：`README.md`、`docs/specs/v0.1-plan.md` 第 4 节 V0.1.1、`docs/README.md` 文档规范。
> 定位：记录 V0.1.1 的选型决策、系统形态与开发约定，不规定函数签名、字段清单等实现细节；具体代码结构在实现计划中确定。

## 1. 目标

确立可运行的最小骨架与开发/测试环境分工基线，为后续版本提供稳定底座。V0.1.1 只交付骨架本身，不实现任何媒体处理、存储接入或业务功能。

## 2. 选型决策

| 项 | 决策 | 理由 |
| --- | --- | --- |
| 仓库形态 | 前后端分离单仓（monorepo） | 单仓便于统一版本、编排与回归；前后端接口契约在同一仓库内演进 |
| 前端 | React 18 + Vite + TypeScript | 计划文档定为 React 系；纯 SPA 最轻量，契合独立后端 |
| 后端 | Python（≥3.12）+ FastAPI | 计划文档定为 FastAPI；异步友好、自带 OpenAPI |
| Python 依赖管理 | uv + `pyproject.toml`（锁文件入库） | 本机已装 uv 0.11.16；可复现、单文件声明 |
| 前端包管理 | npm | 本机已装 npm 11；无需额外安装 |
| 数据库 | 仅 SQLite（SQLAlchemy 2.x 接线） | V0.1.1 无业务数据；SQLite 零依赖满足本地与测试环境骨架需求，后续需更强一致性时再评估迁移 |
| 配置管理 | pydantic-settings，全部走环境变量/`.env` | 环境差异集中管理，凭据不落代码不落仓库 |
| 测试（后端） | pytest + FastAPI TestClient | 计划文档以「接口契约、状态流转」为本地验证重点 |
| 测试（前端） | Vitest + React Testing Library | 与 Vite 同源，配置成本低 |
| 测试环境 | Docker Compose（Ubuntu 24.04） | 计划文档指定；本机不装 Docker，仅写好编排并在测试环境验证 |

## 3. 系统形态与仓库布局

```
LiveReview/
├─ backend/                # Python + FastAPI
│  ├─ app/
│  │  ├─ main.py           # 应用工厂与路由装配
│  │  ├─ config.py         # pydantic-settings 配置
│  │  └─ routers/health.py # 健康检查
│  ├─ tests/
│  ├─ pyproject.toml
│  └─ .env.example         # 本地环境变量样例（无真实凭据）
├─ frontend/               # React + Vite + TypeScript
│  ├─ src/                 # 基础页面（服务状态）
│  ├─ .env.example
│  └─ ...                  # vite / vitest 配置
├─ docker/
│  └─ docker-compose.yml   # 测试环境骨架（Ubuntu 24.04）
└─ docs/                   # 既有文档体系
```

## 4. 组件与数据流

### 4.1 后端

- **配置（config.py）**：用 pydantic-settings 定义配置项，值一律来自环境变量，`.env` 提供本地默认值；`DATABASE_URL` 默认 `sqlite:///./data/liverreview.db`。配置项含 `APP_ENV`、`APP_VERSION`、`DATABASE_URL`、`LOG_LEVEL`，并预留 TOS（`TOS_*`）与媒体工具路径（`FFMPEG_PATH`、`FFPROBE_PATH`）占位。凭据类字段（`TOS_ACCESS_KEY`/`TOS_SECRET_KEY`）只读环境变量、无默认值、禁止打印。
- **数据库接线**：建立 SQLAlchemy 引擎与会话工厂（`sessionmaker`），SQLite 开启必要的并发与线程参数。V0.1.1 只验证引擎可用，不建业务模型、不引入 Alembic。
- **健康检查**：`GET /health` 返回服务名、版本、环境、数据库连通状态与时间戳；数据库不可用时返回降级状态而不崩溃。供编排探针与前端调用。

### 4.2 前端

- **基础页面**：一屏展示服务名、版本、环境，并调用后端 `/health` 显示「后端已连接 / 未连接」状态。这是 V0.1.1 的「可访问基础页面」，不提前做上传界面。
- **API 地址**：通过 `VITE_API_BASE_URL` 注入，Vite dev server 配置代理，本地与 Docker 环境切换清晰。

### 4.3 Docker Compose 测试环境

- 服务：`backend`（Python 3.12 镜像，暴露 8000，带 healthcheck）、`frontend`（Node 构建后由轻量静态服务托管，代理后端）。
- **FFmpeg 挂载点预留**：backend 服务声明 `ffmpeg` 依赖与媒体卷 `/app/media`，但 V0.1.1 仅预留安装位置与挂载点，不启用媒体处理逻辑（符合计划「预留挂载点」）。

## 5. 错误处理与安全

- 配置缺失或非法时启动即报错，错误信息不含凭据值。
- 健康检查数据库异常时返回明确状态，日志记录原因，不向外部暴露堆栈细节。
- TOS AK/SK、`.env`、SQLite 数据文件均已被 `.gitignore` 排除，不入库。

## 6. 测试

- 后端：配置加载（环境变量优先级、凭据无默认值）、健康检查（正常与数据库异常两态）。
- 前端：基础页面渲染与后端状态文案切换。
- 测试环境：`docker compose up` 后后端健康检查通过（本机无 Docker，由测试环境验证）。

## 7. 验收要点（对应 v0.1-plan.md）

- 前后端可在本地启动并访问；后端健康检查通过。
- 测试环境可通过 Docker Compose 拉起，后端健康检查通过。
- 配置文件约定清晰，敏感凭据仅从环境变量读取，不落库不落仓库。
