# V0.8.0 设计文档：复盘准则对齐 V3.2 与分轮专项分析

> 本文是 V0.8.0 的设计文档，属 `specs/` 下的开发任务期间产出。
> 依据：业务方提供的《直播复盘分析准则》V3.2（`docs/直播复盘分析准则V3.2.md`）与其前身 V3.0
> （`docs/直播复盘分析准则V3.0.md`）的差异比对。
> 定位：记录本版的**裁剪口径**、**决策取舍**与**边界**，不规定函数签名与字段清单（看代码即可）。

## 1. 本版要解决的问题

业务方更新了复盘准则（V3.0 → V3.2），新增了大量检核项。旧实现只把准则当作一段文本塞进单次
调用的提示词里，V3.2 的体量已经超出「一次调用讲清一件事」的合理范围：心法检核、样板引用、
重复度统计、违规词排查是四类彼此独立的判断，挤在一次调用里既容易互相稀释，也让失败无法定位。

因此本版做两件事：**把 V3.2 的可观察增量合进分析流程**，并把**一次复盘拆成四轮专项调用**。

## 2. 准则版本差异与合入判定

V3.2 相对 V3.0 的增量，按「本版能否观察、能否合入」分四类：

| 增量 | 判定 | 理由 |
|---|---|---|
| 12 条心法检核项 | 合入 | 只依据语音即可逐条对照 |
| M817 30 句话术样板 | 合入 | 样板引用是对「怎么讲」的判断，语音足够 |
| 违规避坑词库 | 合入 | 逐句可查，且结论可给替换说法 |
| 内容重复度检测 | 合入 | 同一卖点重复几次是可数的 |
| 留资引导频次 | 合入 | 引导话术的出现位置与频次可数 |
| 多角度 TOP3 约束 | 合入 | 属输出契约，程序侧兜底截断 |
| 证据等级三档 | 合入 | 旧版已有，V3.2 收紧到每条判断必标 |
| 主播档案、跨场话术库 | **不合入** | 需要跨任务存储，超出本版范围（见 §4） |
| 经营数据、漏斗定位、OCR/画面识别 | **不合入** | 本版输入只有语音，不可观察 |
| 100 分制评分、月度报告 | **不合入** | 评分口径依赖经营数据，单场无法自证 |

## 3. 裁剪口径（沿用 V0.3 的边界，不放宽）

本版**不扩大输入边界**：仍然只有整场语音转写，没有画面、没有 OCR、没有经营数据。因此：

- **心法检核只判「讲没讲、怎么讲的」，不判「效果好不好」**。效果类心法在结论里只能作为待验证假设，不得写成结论。
- **违规词库只做「表达替换」建议**，不做合规判定——判定权不在本系统。
- **重复度只统计「说过几次」，不推断「观众是否听腻」**。
- 结论里出现的每一个编号（心法、样板）都必须能就地查到原文，界面上可展开、报告里附对照表。

## 4. 决策与理由

- **只做单场，不做跨任务档案**。主播档案与话术库要求「跨场次积累 + 检索」，会引入新的存储形态、归属与生命周期问题，且验收标准会从「这场复盘得对不对」漂移到「档案库准不准」。本版把金句与编号留在单场结论里留痕，不承诺入库与检索；界面显式说明这一点，避免用户以为收录了就等于存进了话术库。
- **编号作为结构化字段落库**，不是把编号写在自由文本里。心法/样板编号要做三件事——界面展开原文、报告附对照表、跨轮次去重——三者都要求它是可枚举的字段。落成结构化字段后，`/api/guideline` 只读端点是它唯一的对外出口，准则原文只在 `app/llm/mindset.py` 存一份。
- **准则原文单一事实来源**。12 条心法、30 句话术样板、违规词库都以 Python 数据结构存放（`app/llm/mindset.py`），提示词渲染、接口返回、报告对照表三者共用同一份数据。此前「准则是一段写死在提示词里的文本」，改一处要同步三处，本版消除这个隐患。
- **心法的 `improve` 字段不进提示词也不出接口**。它是给业务方写改进建议用的内部话术，模型只需要知道「检核什么」（`check`），拿到改进建议反而容易越界替业务方下结论。

## 5. 四轮专项调用

一次复盘拆成四轮，每轮只回答一个问题：

| 轮次 | 名称 | 输入 | 产出 |
|---|---|---|---|
| `structure` | 内容结构 | 整场转写 | 一句话结论、主题分布、关键事件、缺口 |
| `checks` | 六维检核 | 整场转写 + 心法/样板/违规词库 | 分析发现、重复度、违规表达 |
| `attribution` | 问题归因与实验 | **前序轮次的结构化产出**（不重送转写） | TOP 问题、下一场实验动作 |
| `quotes` | 金句采集 | 整场转写 | 金句收录 |

设计要点：

- **归因轮不重送转写**。它需要的是「已经发生了什么」，而不是原始素材。重送一遍既浪费窗口，也给了模型用新素材推翻前序结论的机会。
- **各轮产物按轮次持久化**（`review_passes_json`）。某一轮失败时可以只重跑那一轮，不必把整场重跑一遍——四轮里最贵的两轮是吃转写的，重跑代价不对称。
- **轮次之间不做摘要调用**。合并是结构性的（去重、按时间排序、按准则截断 TOP3），由程序完成，不额外花钱。
- **每轮的 system 共用同一份裁剪准则**，只追加本轮题面与输出契约。这保证四轮看到的是同一套口径，不会出现「结构轮按 A 标准、检核轮按 B 标准」。
- **调用次数上不设节约目标**。四项分析各有其独立上下文需求，本版的选择是「每轮做好一件事」，而不是把成本压到最低。

## 6. 边界与后续

- 本版**不做**：主播档案、跨场话术库、经营数据接入、画面/OCR 识别、100 分制评分、月度报告。
- 本版**没有**用户可编辑的准则配置——准则内容随版本发布，改准则即改代码与提示词。
- 若后续要引入跨场次能力，需要先决定的是「场次的归属与检索口径」，而不是模型侧的实现；那应作为独立版本立项。
