# V0.1.6 设计文档：工作台前端界面

> 本文是 V0.1.6 的设计文档，属 `specs/` 下的开发任务期间产出。
> 依据：本次开发的任务方要求（对 `v0.1-plan.md` 第 4 节 V0.1.6 的调整）、`README.md`、`docs/architecture.md`、`docs/README.md` 文档规范。
> 定位：记录本版的界面结构、视觉取舍与范围变更，不规定函数签名、字段清单等实现细节。

## 1. 目标与范围调整

原 V0.1.6 定义为「结果查看与整场验收」，包含切片回看。本次任务方调整如下：

| 项 | 原定 | 本版改为 |
| --- | --- | --- |
| 界面定位 | 在既有页面上补结果页与时间线 | 重新设计一套完整的商务风工作台界面，「上传 → 探测 → 切分 → 查看」流程移植到新界面跑通 |
| 切片回看 | 点击切片回看对应视频 | **撤销**。实现复杂且需求性不强；主页不展示切片后的视频，不提供播放/回看入口 |
| 切片结果呈现 | 列表 + 回看入口 | 仅以文字信息呈现：序号、原视频时间范围、时长、体积、处理状态 |
| 用户登录 | 无 | 预置功能区，后端不实现 |
| 历史记录 | 无 | 预置功能区，读既有任务列表接口 |

调整后的验收边界：新界面下完整跑通上传、探测、切分与结果查看，即视为 V0.1 整体验收通过。

## 2. 界面结构

```
┌────────────────────────────────────────────────────────────┐
│ 直播视频复盘分析工作台                        [用户登录]    │ 页眉
├──────────────┬─────────────────────────────────────────────┤
│ 新建上传任务 │ 工作区                                       │
│              │  ┌ 上传入口（未开始）                        │
│ 历史记录     │  ├ 上传进度（字节）                          │
│  ● 任务 A    │  └ 任务结果                                  │
│  ○ 任务 B    │     处理进度刻度轴                           │
│              │     1 媒体信息                               │
│              │     2 切分结果 + 切片列表                     │
└──────────────┴─────────────────────────────────────────────┘
```

- **页眉**：项目中文名称与用户区（登录为预留）。服务状态行（后端连通性、对象存储配置、版本）在 V0.1.6.1 中移除：这些都是测试阶段的验证字段，正式页面不再出现。
- **侧栏**：新建上传任务入口 + 历史记录。历史记录读既有 `GET /api/tasks`，按上传时间倒序，点击在工作区只读展示该任务结果。
- **工作区**：三种内容之一——上传入口、上传与处理过程、从历史记录打开的任务。

## 3. 视觉设计

母题是「一档商务工具里的时间轴桌面」：录屏复盘的一切证据都是时刻与片段区间，因此**时刻、体积、编码这类可被逐项核对的取值统一用等宽字体**，让用户能逐行比对，而不是把数字混进正文。这层区分承担的是可读性，不是装饰。

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 页眉 | `#16283A` 深藏青 | 商务工具的稳定锚点 |
| 工作区底色 | `#EEF1F5` 冷灰白 | 与白色面板拉开层次 |
| 面板 | `#FFFFFF`，1px `#D7DDE5` 边框，圆角 3px | 不用卡片软阴影与渐变装饰 |
| 强调色 | `#1D5BAB` 企业蓝 | 全站唯一高饱和色，只用于主操作与当前态 |
| 提示色 | `#7D5200` 琥珀 + `#FBF4E4` 底 | 失败与需留意，配合左侧竖条与字重，不单靠颜色表意 |
| 字体 | 系统无衬线做界面 + 等宽做时刻与参数 | 不引网络字体，离线与容器内一致 |
| 字号 | 20 / 17 / 15 / 13 / 12px 五级 | V0.1.6.1 起全站只用这五级，层级靠字号与颜色拉开 |

结构即信息的三处编排：

1. **处理进度是刻度轴**：五段刻度与后端进度取值一一对应（0 认领 / 20 探测 / 25 转换 / 40~98 切片 / 100 完成）。刻度块实心＝已完成、空心加粗＝进行中、空心细＝未开始。用刻度而不是通用进度条，是因为阶段本身就是用户要看的结论。
2. **切片列表给出位置条**：每片按原视频总时长换算成比例区间，同时表达「这一片在整场的什么位置」与「各片相对长度」，是「覆盖整场、交界可检查」这一验收要求的直接视觉对应。
3. **历史记录挂在一条竖轴上**：与视频时间轴的隐喻一致，节点即任务。

## 4. 前端模块

| 文件 | 职责 |
| --- | --- |
| `App.tsx` | 壳层：页眉 + 侧栏 + 工作区，持有健康状态、任务列表、当前打开的任务与登录态 |
| `Header.tsx` | 页眉：项目名、用户区、服务状态 |
| `Sidebar.tsx` | 新建任务入口与历史记录列表 |
| `LoginDialog.tsx` | 登录弹层（预留功能区，不请求后端） |
| `Workbench.tsx` | 工作区：本次上传流程（选文件、分片上传、轮询任务）与历史任务的只读展示 |
| `UploadProgress.tsx` | 上传字节进度，与任务处理进度分开呈现 |
| `TaskSummary.tsx` | 任务结果：进度刻度轴、探测结论、切分结论与操作入口 |
| `ClipTable.tsx` | 切片列表（仅文字信息与位置条，无回看入口） |
| `format.ts` | 文案与数值格式化（时间码、体积、编码、状态标签） |
| `api.ts` | 后端契约：新增 `Health` 类型与 `fetchHealth`，其余不变 |

原 `UploadPanel.tsx` 被 `Workbench.tsx` 取代并删除，`UploadPanel.test.tsx` 更名为 `Workbench.test.tsx`。

`download_url` 仍留在 `TaskClip` 契约中（后端照常返回），前端不再消费——撤销切片回看后，界面不展示任何预签名地址。

## 5. 预留功能区的处理方式

登录与历史记录的账号隔离都未接入后端。界面对此的态度是**明确说明，而不是假装可用**：

- 登录弹层写明「登录功能为预留功能区。当前版本不校验账号、不请求后端，填写后仅用于界面显示」；提交后只切换页眉的账号态，不发送任何请求。
- 历史记录读的是既有任务列表接口，因此**列出的是本服务上的全部任务，不区分账号**；侧栏标注「预留」并说明账号隔离待登录功能接入后提供。
- 若某天接入真实鉴权，需要改动的只有这两处：`LoginDialog` 的提交改为真实请求，侧栏改为按当前账号过滤。

## 6. 测试

**本地（不需要 FFmpeg / TOS）**：

- 回归既有链路用例：分片上传、缺片提示、上传失败重来、任务失败重试、删除及其取消与失败分支、探测结论展示与占位、切分结论与切片列表。
- 新增壳层用例：页眉中文项目名与登录入口、登录弹层的预留说明与账号态切换、账号为空时的提示、历史记录列出任务并点击打开、历史空态、历史读取失败不影响工作区。
- 新增切片呈现用例：序号补零与时间范围、位置条按时间轴换算（第二片接在第一片之后）、**片段行没有任何链接且页面无 `video` 元素**（撤销回看的断言）。

**测试环境（仍需验证）**：真实 TS 录屏在测试环境跑通「上传 → 探测 → 切分 → 查看」的新界面流程。

## 7. 验收要点（对应调整后的 V0.1.6）

- 页眉显示项目中文名称，预置用户登录组件与历史记录区域。
- 新界面下跑通「上传 → 探测 → 切分 → 查看」完整流程。
- 切片结果以文字形式呈现，主页不展示视频、不提供回看。
- 关闭页面不影响后台处理；处理失败可查看原因并重新执行。
- 全部满足 `README.md` V0.1 的验收要点。

## 7.1 V0.1.6.1 补丁：界面深度优化

V0.1.6 首版界面在宽屏下重心散、层级弱，且把测试阶段的验证字段带到了正式页面。本补丁只改前端，接口契约与后端不变。

| 项 | 首版 | 本补丁 |
| --- | --- | --- |
| 页眉 | 品牌行 + 服务状态行（后端 / 对象存储 / 版本） | 去掉服务状态行，收成单行紧凑条；这三项属测试阶段验证字段，不出现在正式页面 |
| 任务标题 | 任务 id 与对象键一并展示 | 只留文件名与「原始文件体积 · 时长」，内部标识不再露出 |
| 侧栏 | 「预留」标签 + 两行说明 | 去掉标签，说明压到一句 |
| 字号 | 15px 正文配 17px 标题，层级差不足 | 20 / 17 / 15 / 13 / 12px 五级字号，全站统一 |
| 媒体信息 | `auto-fit` 网格，窄容器下掉成孤项 | 时长单独成列，参数清单改「标签—取值」成对行 |
| 长文件名 | `word-break: break-all` 逐字断行 | `overflow-wrap: anywhere`，只在必要时断 |
| 主区宽度 | `62rem` 且不居中，宽屏右侧留大片空白 | 整页限制在 `84rem` 内容框内居中，工作区上限 `60rem` |

## 8. 不在本版范围

- 用户登录的真实实现（账号体系、鉴权、会话）与历史记录的账号隔离。
- 切片回看、视频播放与事件定位：本章程已撤销，V0.1 范围内不再提供。
- 内容时间线、关键事件与复盘报告（V0.3、V0.4）。
- 前端路由库与状态管理库：界面只有一种工作区，用组件状态足够，不引入额外依赖。

## 9. 已知限制

- 历史记录列出全部任务，多用户场景下会互相看到；这是预留功能区的直接后果，随登录接入一并解决。
- 本机未安装 FFmpeg，本地只能验证到「探测失败并给出原因」这一步；真实媒体的完整链路只在测试环境验证。
- 切片列表在窄屏（≤40rem）隐藏位置条并改为横向滚动，定位依据回落到时间范围列。
